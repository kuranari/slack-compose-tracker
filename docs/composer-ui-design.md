# 入力欄まわりのボタンの置き方の設計メモ

2026-11-03 作成。経過時間・AI の提案・定型文のボタンを、Slack の入力欄の UI になじむように置く。

## 調べたこと（2026-11-03、実機）

- 入力欄（`.c-wysiwyg_container`）は、上から書式ツールバー、入力欄（Quill）、下の列（`role="toolbar"`、添付・`Aa`・絵文字・`@` と送信ボタン）の 3 段。メインとスレッドで作りは同じ。
- 書式ツールバーは `Aa`（`[data-qa="texty_composer_button"]`）で隠すと、中身が DOM から消える。表示し直すと作り直され、差し込んだ要素も消える。状態は全体の設定で、リロードしても残る。
- 下の列は、書式の表示・非表示、入力、スレッドの開閉では作り直されない。別の画面に移って戻ると作り直される。
- Slack は幅が狭いと、ボタンを `⋯` に畳む。自前の要素を列の中に入れると、この計算を狂わせうる。
- Slack のボタンは 28×28px、角丸 4px、背景は透明。

## 置き方

| 観点                                | A. 書式ツールバーに差し込む    | **B. 重ねて表示し、下の列に位置を合わせる** | C. 下の列に要素を差し込む        |
| ----------------------------------- | ------------------------------ | ------------------------------------------- | -------------------------------- |
| 見た目のなじみ                      | ◎                              | ○ Slack のボタンを真似る                    | ◎                                |
| 書式ツールバーを隠したとき          | × 置き場が消える               | ◎ 影響なし                                  | ◎ 影響なし                       |
| Slack の作り直しへの強さ            | △ 切り替え・画面の移動で消える | ◎ Slack の DOM に触らない                   | ○ 画面の移動で消えるので入れ直す |
| Slack のレイアウトへの影響          | × 幅の計算を壊しうる           | ◎ なし                                      | △ `⋯` の畳み方に影響しうる       |
| 「Slack の DOM に書き込まない」方針 | ×                              | ◎                                           | △                                |

**採用: B**（ユーザー確認済み）。安全さと今の方針を優先した。

- `body` 直下の Shadow DOM に fixed で置き、送信ボタン（`[data-qa="wysiwyg-container_suffix"]`）の左に、縦の中心をそろえて並べる（`lib/composer-overlay.ts`）。
- Slack のボタンの右端は、並んでいる `button` そのものの矩形で測る。ボタンの入れ物は送信ボタンの手前まで伸びているので、入れ物では測れない。
- 自前のボタンを置く隙間が無いとき（狭いスレッドなど）は、入力欄の右上に逃がす。
- 位置は毎フレーム（`requestAnimationFrame`）合わせ直す。中身（経過時間など）の更新は 0.5 秒ごと。最初は位置も 0.5 秒ごとにしていたが、読み込み直後に Slack が画面下にバナーを出して入力欄が 52px 上に動き、ボタンが 0.1 秒ほど元の位置に取り残された（2026-11-03 に計測）。毎フレームにしてからは、ずれは 1 フレーム以内。値が変わったときだけ書き込む。
- アイコンの色は Slack のボタン（`@`）の色を読んで合わせる。ダークテーマでの見た目は未確認。
- ボタンを押しても入力欄のフォーカスは外れない（`mousedown` の既定動作を止める）。定型文の検索欄と AI の提案の本文だけはフォーカスを受け取る。提案の本文は、マウスでなぞって選び `Cmd+C` でコピーできる（2026-11-03）。そこで打ったキーやコピーの操作は Slack に届かないよう、Shadow DOM の外への伝わりを止める（届くと、入力欄に移ったり、Slack のコピーの処理が選んだ文字を上書きしたりしうる）。

## 並べるもの

左から順に、次の 3 つを並べる。

1. 経過時間：下書きがあるときだけ。5 分で黄、10 分で赤。
2. AI の提案のボタン：オプション画面で有効にしていて、下書きがあるときだけ。5 分を超えると目立たせる。
3. 定型文のボタン：常に出す（空の入力欄から定型文で書き始められるように）。

## 見直す条件

- Slack の DOM が変わって位置がずれたら、`lib/slack-dom.ts` の `composerFooter` を直す。
- 重ねる方式のずれが気になるようなら、C（下の列に差し込み、消えたら入れ直す）を検討する。
