# 作成時間の計測と保存の設計メモ

2026-10-29 時点。

## 用語と計測の定義

- **下書き**: 1 つの入力欄に入力された、送信または破棄されるまでのテキスト。
  - キーは `teamId/channelId`（チャンネル）か `teamId/channelId/threadTs`（スレッド）。
- **開始**: 入力欄が空でない状態で、最初の `input` イベントを観測した時刻。
- **終了**: 入力欄が空になったのを観測した時刻。
  - 送信操作（Enter / `Cmd+Enter` / 送信ボタン）から `SEND_WINDOW_MS`（3 秒）以内に空になれば **送信**。終了時刻は送信操作の時刻にする。
  - それ以外は **破棄**。全文を手で消した場合もここに入る。
- 経過時間の表示（入力欄右上のバッジ）と記録は、どちらも同じ「開始」を基準にする。

### 既知の割り切り

- 他のチャンネルに移っていた時間も経過時間に含まれる。
  - Slack はチャンネルごとに下書きを保持するので、戻ってきたら同じ下書きの続きとして扱う。
- 拡張機能を読み込む前からあった下書き（ページ読み込み時点で入力欄に文字がある）は、開始が不明なので次の入力から計測する。
- Threads 一覧など、URL がチャンネルを指さない画面の入力欄は追跡しない。
- スレッドを開いても URL は変わらない。`threadTs` は、スレッドペイン先頭の `[data-msg-ts]`（親メッセージ）から取る。

## 保存先

| 観点                   | A. `chrome.storage.local` | **B. A ＋ JSON/CSV 書き出し** | C. File System Access API  | D. Native Messaging            |
| ---------------------- | ------------------------- | ----------------------------- | -------------------------- | ------------------------------ |
| 実装コスト             | ◎                         | ○                             | △ 権限の再取得の UI が必要 | × ホストプログラムの配布が必要 |
| ファイルとして扱えるか | ×                         | ○ 手動で書き出す              | ◎ 自動                     | ◎ 自動                         |
| テストのしやすさ       | ◎ `fakeBrowser`           | ◎                             | △                          | △                              |
| 拡張機能を削除したとき | 消える                    | 書き出した分は残る            | 残る                       | 残る                           |

**採用: B**（ユーザー確認済み）。まずは手軽さとテストのしやすさを優先した。

### 記録の粒度

| 案                       | 長所                             | 短所                                                |
| ------------------------ | -------------------------------- | --------------------------------------------------- |
| キー入力ごとの生イベント | 後から定義を変えて集計し直せる   | 1 日数千件で `storage.local` の 10MB をすぐ使い切る |
| **下書き単位（採用）**   | 小さい。表示と同じ定義で一貫する | 開始・終了の定義を変えても過去分は再計算できない    |

折衷として、下書き単位の記録に `inputCount` と `length` も残している。

### 書き込みの経路

- content script → `runtime.sendMessage` → background → `storage.local`。
- 書き込むのは background だけで、`appendRecord` の中で get→set を直列化している。複数タブから同時に追記しても取りこぼさないため。
- popup は読み取り専用。

## 層の分け方

| ファイル                 | 層               | 責務                                                                |
| ------------------------ | ---------------- | ------------------------------------------------------------------- |
| `lib/slack-dom.ts`       | IO（Slack DOM）  | セレクタと DOM の探索。Slack の変更で壊れたら直すのはここだけ       |
| `lib/draft-session.ts`   | ドメイン（純粋） | 開始・終了・送信か破棄かの判定                                      |
| `lib/compose-record.ts`  | ドメイン（純粋） | 記録の型、集計、CSV 変換                                            |
| `lib/duration.ts`        | 純粋             | 表示用の時間フォーマット                                            |
| `lib/record-store.ts`    | IO（storage）    | 永続化                                                              |
| `lib/elapsed-badge.ts`   | IO（UI）         | バッジの描画。Shadow DOM に fixed 配置し、Quill の DOM には触れない |
| `entrypoints/content.ts` | 組み立て         | イベントの購読、定期チェック、各層の接続                            |

## 見直す条件

- 記録が数万件を超えて `storage.local` の容量や読み込み速度が問題になったら、IndexedDB に移すか、古い記録を間引くことを検討する。
- 書き出しを手で行うのが負担になったら、C（File System Access API）を検討する。
- 「離席時間を除いた実作業時間」が欲しくなったら、`lastInputAt` を使ったアイドル判定を追加する。その場合は記録の型の変更も検討する。
